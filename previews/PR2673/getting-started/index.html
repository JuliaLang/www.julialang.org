Getting started

Pick a starter kit

The General registry holds over 12,000 packages. To begin, you need a handful. Below are the ones people actually use most, grouped by how you'll work rather than by field.

No Julia yet? Install it first; it takes a minute. New to the language? Read what Julia is, or start with the manual.

julia> ]
(@v1.13) pkg> add CSV DataFrames
  1. 1
    Press ] at the julia> prompt. It turns blue: you're in package mode.
  2. 2
    Paste an add line. For a project, run activate . first so its packages stay with it.
  3. 3
    Press Backspace to leave, then using them. If you forget step 2, using offers to install for you.

Every session: the toolbelt

Whatever you end up doing, these make every session better. Choose the ones you want, and we'll write your startup.jl so they load each time you start Julia.

1. Install them into your default environment

pkg> add DocBrowser Revise

2. Save this as ~/.julia/config/startup.jl

if isinteractive()
    using Revise
    using DocBrowser
end

On Windows the file lives at %USERPROFILE%\.julia\config\startup.jl. Revise always goes first, so it can track everything loaded after it.

And somewhere to type:

VS CodeThe Julia extension: editor, REPL, plots, debugger and profiler in one window. Pluto.jlReactive notebooks: change a cell and everything that depends on it reruns. Add PlutoUI.jl for sliders and buttons. IJulia.jlJulia in Jupyter notebooks, and in Quarto reports.

Then pick how you'll work

Each kit starts with one or two packages per step. Where there's a choice, it says "or", and you only need one.

Explore data

You have data and questions: read it, reshape it, plot it, fit it.

  • Read
    CSV.jl and DataFrames.jl: load files into tables, then filter, join and group them.
  • Plot
    Plots.jl: one quick syntax for line, scatter, histogram and heatmap plots. Or CairoMakie.jl for publication figures.
  • Fit
    Distributions.jl: sample, fit and evaluate nearly every probability distribution.
Wrangle
DataFramesMeta.jl · Chain.jl
Files
XLSX.jl · Arrow.jl · JLD2.jl · SQLite.jl · DuckDB.jl
Stats
StatsBase.jl · GLM.jl · HypothesisTests.jl · MixedModels.jl · Turing.jl
Models
MLJ.jl (trees, boosting, clustering, tuning)
Plots
AlgebraOfGraphics.jl · GLMakie.jl · UnicodePlots.jl
Taste it 
using CSV, DataFrames, Plots, Distributions, Statistics

CSV.write("data.csv", DataFrame(x = randn(1000), group = rand(["a", "b"], 1000)))
df = CSV.read("data.csv", DataFrame)

combine(groupby(df, :group), :x => mean)

d = fit(Normal, df.x)
histogram(df.x; normalize = true, label = "data")
plot!(x -> pdf(d, x); label = "fit", linewidth = 3)

Model and solve

You can write down the maths. A solver does the rest.

  • Simulate
    OrdinaryDiffEq.jl: fast, adaptive solvers for ordinary differential equations, from simple to very stiff.
  • Optimize
    JuMP.jl with the HiGHS solver, for constrained problems written as they look on paper. Or Optim.jl to minimize a plain function.
  • Differentiate
    ForwardDiff.jl: exact derivatives of ordinary Julia code.
  • Learn
    Flux.jl: neural networks that are plain Julia all the way down.
Equations
SciML (SDEs, DAEs, delays) · ModelingToolkit.jl · Symbolics.jl · NonlinearSolve.jl · Roots.jl
Numerics
Interpolations.jl · QuadGK.jl · FFTW.jl · DSP.jl · Graphs.jl · Images.jl
Units
Unitful.jl · Measurements.jl (error bars)
Solvers
Ipopt.jl (nonlinear)
Learning
Lux.jl · Enzyme.jl (gradients of fast, mutating code)
Taste it 
using OrdinaryDiffEq

decay(u, p, t) = -p * u
sol = solve(ODEProblem(decay, 1.0, (0.0, 5.0), 0.8))
sol(2.5)   # ≈ exp(-2) = 0.135

Make it fast

It works. Now measure it, find the slow part, fix it, and use every core.

  • Measure
    BenchmarkTools.jl, from the toolbelt.
  • Find
    The built-in profiler (@profview in VS Code), and the manual's performance tips.
  • Fix
    StaticArrays.jl: small fixed-size arrays with no allocation.
  • Threads
    OhMyThreads.jl: multithreaded map, reduce and loops. Start Julia with -t auto.
  • GPU
    Pick the one for your hardware: CUDA.jl (NVIDIA), Metal.jl (Apple) or AMDGPU.jl.
Dig in
JET.jl (@report_opt) · Cthulhu.jl
Portable
KernelAbstractions.jl (one kernel, any GPU)
Startup
PrecompileTools.jl
Taste it 
# start Julia with: julia -t auto
using BenchmarkTools, OhMyThreads

@btime sum(x -> sin(x)^2, 1:10^7)
@btime tmapreduce(x -> sin(x)^2, +, 1:10^7)

Build and ship

The unit of work is a repo: a package, a command-line tool or a web service.

  • Package
    PkgTemplates.jl sets up a package with CI. Write tests with the Test stdlib, docs with Documenter.jl, and catch common mistakes with Aqua.jl.
  • Ship
    JuliaC.jl compiles a program into a native executable. Pkg apps let people install your package as a command-line tool.
  • Serve
    HTTP.jl and JSON.jl for clients and servers; Oxygen.jl for routes in a few lines.
Style
JuliaFormatter.jl · Runic.jl
Tests
TestEnv.jl · TestItemRunner.jl
Tools
ArgParse.jl · ProgressMeter.jl · PackageCompiler.jl
Web apps
Genie.jl · Bonito.jl
Taste it 
using PkgTemplates

t = Template(; user = "your-github-name",
               plugins = [GitHubActions(), Documenter{GitHubActions}()])
t("MyPackage")

Work through an agent

You describe, an AI agent types. Give it a Julia that answers in milliseconds.

  • Run
    JuliaDaemon.jl: one warm session per project, with Revise loaded. The agent runs jld eval instead of starting Julia on every call, and you can jld connect to the same session.
  • Check
    JET.jl finds errors without running the code, Runic.jl formats it one fixed way, and TestItemRunner.jl runs one test at a time.
Review
ExplicitImports.jl (reports implicit and stale imports)
MCP
julia-mcp (persistent sessions over MCP; a Python server, not a Julia package)
Taste it 
# teach your agent to use jld
jld install

# the first call starts a session
cd MyPkg
jld eval 'using MyPkg; MyPkg.foo()'

# later calls are warm, edits live
jld run test/runtests.jl

Didn't find yours?

There are over 12,000 more. Some places to look:

  • JuliaHub Search every registered package and its docs.
  • Package comparisons Help choosing between similar packages.
  • Ask on Discourse The "First steps" category is friendly and quick.
Coming from Python, R or MATLAB? PythonCall.jl calls any Python library (with CondaPkg.jl for its dependencies), RCall.jl does the same for R, and the manual lists the noteworthy differences.

Then mix them

Julia packages work together even when their authors never planned it. That's multiple dispatch at work, and it's why a small kit goes a long way.

Write a function once…

# Newton's method, for plain numbers
function mysqrt(x)
    t = x
    for _ in 1:10
        t = (t + x / t) / 2
    end
    return t
end

…and every package can use it

julia> using Measurements, ForwardDiff

julia> mysqrt(2.0 ± 0.1)     # error bars, propagated
1.414 ± 0.035

julia> mysqrt(big"2.0")      # as many digits as you like
1.414213562373095048801688724209698078569671875376948073176679737990732478462119

julia> ForwardDiff.derivative(mysqrt, 2.0)   # an exact derivative
0.35355339059327373

Measurements.jl and ForwardDiff.jl know nothing about mysqrt, and mysqrt knows nothing about them. With CUDA.jl, mysqrt.(CUDA.rand(10^6)) runs it on a GPU too.

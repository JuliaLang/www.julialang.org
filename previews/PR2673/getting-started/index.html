Pick a few packages

The General registry holds over 12,000 packages. To begin, a handful is often enough. Below are the ones people actually use most, grouped by the kind of work you might do.

No Julia yet? Install it first; it takes a minute. New to the language? Read what Julia is, or start with the manual.

Adding packages

  1. Press ] at the julia> prompt. It turns blue: you're in package mode.

  2. Type an add line, such as add CSV DataFrames. For a project, run activate . first so its packages stay with it.

  3. Press Backspace to leave, then using them.

Or skip package mode: type using CSV at the julia> prompt, and if CSV isn't installed yet, the REPL asks whether to install it.

Every session: the toolbelt

Whatever you end up doing, these make every session better.

  • Revise.jl: edit your code, keep your session. Changes apply without a restart.

  • DocBrowser.jl: every manual and docstring, browsable without leaving the REPL. Press Enter at an empty help?> prompt.

  • BenchmarkTools.jl: @btime gives timings you can trust.

  • Infiltrator.jl: put @infiltrate in a function to stop there and inspect it.

Install the ones you want into your default environment:

pkg> add Revise DocBrowser

Then load them each time Julia starts, by saving this as ~/.julia/config/startup.jl (on Windows, %USERPROFILE%\.julia\config\startup.jl):

if isinteractive()
    using Revise
    using DocBrowser
end

Revise goes first, so it can track everything loaded after it.

And somewhere to type:

  • VS Code with the Julia extension: editor, REPL, plots, debugger and profiler in one window.

  • Pluto.jl: reactive notebooks. Change a cell and everything that depends on it reruns. Add PlutoUI.jl for sliders and buttons.

  • IJulia.jl: Julia in Jupyter notebooks, and in Quarto reports.

Then pick what you'd like to do

Each section lists one or two packages per step. Where there's a choice, it says "or", and you only need one.

Explore data

You have data and questions: read it, reshape it, plot it, fit it.

  • Read: CSV.jl and DataFrames.jl load files into tables, then filter, join and group them. add CSV DataFrames

  • Plot: Plots.jl has one quick syntax for line, scatter, histogram and heatmap plots. Or CairoMakie.jl for publication figures. add Plots

  • Fit: Distributions.jl samples, fits and evaluates nearly every probability distribution. add Distributions

using CSV, DataFrames, Plots, Distributions, Statistics

CSV.write("data.csv", DataFrame(x = randn(1000), group = rand(["a", "b"], 1000)))
df = CSV.read("data.csv", DataFrame)

combine(groupby(df, :group), :x => mean)

d = fit(Normal, df.x)
histogram(df.x; normalize = true, label = "data")
plot!(x -> pdf(d, x); label = "fit", linewidth = 3)

Next steps: wrangling with DataFramesMeta.jl and Chain.jl; files with XLSX.jl, Arrow.jl, JLD2.jl, SQLite.jl and DuckDB.jl; statistics with StatsBase.jl, GLM.jl, HypothesisTests.jl, MixedModels.jl and Turing.jl; machine learning with MLJ.jl; more plotting with AlgebraOfGraphics.jl, GLMakie.jl and UnicodePlots.jl.

Model and solve

You can write down the maths. A solver does the rest.

  • Simulate: OrdinaryDiffEq.jl has fast, adaptive solvers for ordinary differential equations, from simple to very stiff. add OrdinaryDiffEq

  • Optimize: JuMP.jl with the HiGHS solver, for constrained problems written as they look on paper. Or Optim.jl to minimize a plain function. add JuMP HiGHS

  • Differentiate: ForwardDiff.jl gives exact derivatives of ordinary Julia code. add ForwardDiff

  • Learn: Flux.jl builds neural networks that are plain Julia all the way down. add Flux

using OrdinaryDiffEq

decay(u, p, t) = -p * u
sol = solve(ODEProblem(decay, 1.0, (0.0, 5.0), 0.8))
sol(2.5)   # ≈ exp(-2) = 0.135

Next steps: more equations with SciML (SDEs, DAEs, delays), ModelingToolkit.jl, Symbolics.jl, NonlinearSolve.jl and Roots.jl; numerics with Interpolations.jl, QuadGK.jl, FFTW.jl, DSP.jl, Graphs.jl and Images.jl; units and error bars with Unitful.jl and Measurements.jl; nonlinear optimization with Ipopt.jl; more machine learning with Lux.jl and Enzyme.jl (gradients of fast, mutating code).

Make it fast

It works. Now measure it, find the slow part, fix it, and use every core.

  • Measure: BenchmarkTools.jl, from the toolbelt. add BenchmarkTools

  • Find: the built-in profiler (@profview in VS Code), and the manual's performance tips.

  • Fix: StaticArrays.jl gives small fixed-size arrays with no allocation. add StaticArrays

  • Threads: OhMyThreads.jl has multithreaded map, reduce and loops. Start Julia with -t auto. add OhMyThreads

  • GPU: pick the one for your hardware: CUDA.jl (NVIDIA), Metal.jl (Apple) or AMDGPU.jl.

# start Julia with: julia -t auto
using BenchmarkTools, OhMyThreads

@btime sum(x -> sin(x)^2, 1:10^7)
@btime tmapreduce(x -> sin(x)^2, +, 1:10^7)

Next steps: dig into slow code with JET.jl (@report_opt) and Cthulhu.jl; write one kernel for any GPU with KernelAbstractions.jl; cut load times with PrecompileTools.jl.

Build and ship

The unit of work is a repo: a package, a command-line tool or a web service.

  • Package: PkgTemplates.jl sets up a package with CI. Write tests with the Test stdlib, docs with Documenter.jl, and catch common mistakes with Aqua.jl. add PkgTemplates Documenter Aqua

  • Ship: JuliaC.jl compiles a program into a native executable. Pkg apps let people install your package as a command-line tool. app add JuliaC

  • Serve: HTTP.jl and JSON.jl for clients and servers; Oxygen.jl for routes in a few lines. add HTTP JSON Oxygen

using PkgTemplates

t = Template(; user = "your-github-name",
               plugins = [GitHubActions(), Documenter{GitHubActions}()])
t("MyPackage")

Next steps: formatting with JuliaFormatter.jl or Runic.jl; testing with TestEnv.jl and TestItemRunner.jl; command-line tools with ArgParse.jl, ProgressMeter.jl and PackageCompiler.jl; web apps with Genie.jl and Bonito.jl.

Work through an agent

You describe, an AI agent types. Give it a Julia that answers in milliseconds.

  • Run: JuliaDaemon.jl keeps one warm session per project, with Revise loaded. The agent runs jld eval instead of starting Julia on every call, and you can jld connect to the same session. app add JuliaDaemon

  • Check: JET.jl finds errors without running the code, Runic.jl formats it one fixed way, and TestItemRunner.jl runs one test at a time. add JET Runic TestItemRunner

# teach your agent to use jld
jld install

# the first call starts a session
cd MyPkg
jld eval 'using MyPkg; MyPkg.foo()'

# later calls are warm, edits live
jld run test/runtests.jl

Next steps: review imports with ExplicitImports.jl; or use julia-mcp for persistent sessions over MCP (a Python server, not a Julia package).

Coming from Python, R or MATLAB?

PythonCall.jl calls any Python library (with CondaPkg.jl for its dependencies), RCall.jl does the same for R, and the manual lists the noteworthy differences. add PythonCall CondaPkg

Didn't find yours?

There are over 12,000 more. Some places to look:

  • JuliaHub: search every registered package and its docs.

  • Package comparisons: help choosing between similar packages.

  • Discourse: the "First steps" category is friendly and quick.

  • Chat: Zulip, Slack, Discord and more, if you'd rather talk in real time.

  • JuliaCon talks: years of package demos and workshops, free on YouTube.

Then mix them

Julia packages work together even when their authors never planned it. That's multiple dispatch at work, and it's why a few packages go a long way.

Write a function once:

# Newton's method, for plain numbers
function mysqrt(x)
    t = x
    for _ in 1:10
        t = (t + x / t) / 2
    end
    return t
end

and every package can use it:

julia> using Measurements, ForwardDiff

julia> mysqrt(2.0 ± 0.1)     # error bars, propagated
1.414 ± 0.035

julia> mysqrt(big"2.0")      # as many digits as you like
1.414213562373095048801688724209698078569671875376948073176679737990732478462119

julia> ForwardDiff.derivative(mysqrt, 2.0)   # an exact derivative
0.35355339059327373

Measurements.jl and ForwardDiff.jl know nothing about mysqrt, and mysqrt knows nothing about them. With CUDA.jl, mysqrt.(CUDA.rand(10^6)) runs it on a GPU too.
